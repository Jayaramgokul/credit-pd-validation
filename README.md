A probability-of-default (PD) model for home-equity loans, followed by the kind
of **independent model validation** a bank's second line would run before
letting it near provisions or capital. The validation report is generated by
code, so every number in it can be reproduced with one command.

**Read the output first: [VALIDATION_REPORT.md](VALIDATION_REPORT.md)**

## What the validation found

The headline is that the most important problems were invisible to the usual
accuracy metrics.

| # | Severity | Finding |
|---|---|---|
| F1 | High | My **2023 approach** (median imputation + SMOTEENN rebalancing) predicts an average PD of **39.5%** for a portfolio that defaults at **20.0%**. Rebalancing makes the training data 49.7% bad, so the model learns the wrong base rate. Fine for a classifier; wrong for a PD model. |
| F2 | High | When the debt-to-income field is missing, the default rate is **62%** against **9%** when present. The variable's information value (1.79) is far above the usual "too good to be true" level. Without it, Gini falls from 0.78 to 0.57. If it goes missing *because of* the outcome, that is target leakage. |
| F3 | Medium | The scorecard is right on average (20.3% vs 20.0%) but **not conservative** in one grade: PD 7.0%, observed 13.2%. |
| F4 | Medium | A gradient-boosting benchmark reaches Gini **0.91** vs the scorecard's **0.78**, with non-overlapping bootstrap intervals. The scorecard leaves real performance on the table. |
| F5 | Low | All coefficients have the correct sign; four weak variables could be pruned. |
| F6 | Low | Stability can only be tested weakly: the data has no dates, so no out-of-time sample exists. Stated, not hidden. |

Overall opinion: the scorecard is conceptually sound and much better than the
2023 version, but **not fit for use** until F2 is explained and F3 is fixed.

## The three models

| Model | What it is | Hold-out Gini | Mean PD vs observed 20.0% |
|---|---|---:|---:|
| **Champion** | Weight-of-evidence logistic scorecard, missing values kept as their own bin | 0.778 | 20.3% |
| **Legacy (2023)** | Reconstruction of my earlier notebook: median imputation, SMOTEENN, logistic regression | 0.559 | 39.5% |
| **Challenger** | Gradient boosting on raw features, used only as a benchmark | 0.912 | 19.6% |

This repo replaces a [2023 notebook of mine](https://github.com/Jayaramgokul/Risk-management-using-ML)
(now archived). Validating my own earlier work was
deliberate: the legacy model shows two mistakes that are common in practice
(rebalancing a PD model, and imputing away informative missingness), and the
report shows how a validator catches and quantifies them.

## What is tested

| Area | Tests |
|---|---|
| Data | checksum, schema, missingness and its link to default |
| Conceptual soundness | information value per variable, correlation screen, coefficient signs |
| Discrimination | Gini, KS, bootstrap 95% intervals, train vs hold-out gap |
| Calibration | mean PD vs observed rate, Hosmer-Lemeshow, per-grade exact binomial test, Brier score |
| Stability | Population Stability Index on the score and on every variable |
| Benchmarking | champion vs gradient-boosting challenger |
| Sensitivity | performance with the most powerful variable removed |

The metrics themselves have **known-answer tests** (`tests/`): perfect ranking
must give Gini 1, identical samples must give PSI 0, doubled PDs must fail
Hosmer-Lemeshow, and so on. A validator's tools should be validated too.

## Run it

```bash
git clone https://github.com/Jayaramgokul/credit-pd-validation.git && cd credit-pd-validation
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m pytest tests/ -q        # 17 tests
python -m pdval.report            # rebuilds VALIDATION_REPORT.md and the figures (~15s)
```

## Layout

```
pdval/
  data.py      load + checksum, schema checks, stratified split, missingness profile
  woe.py       weight-of-evidence binning and information value
  models.py    champion scorecard, legacy reconstruction, challenger benchmark
  metrics.py   Gini, KS, bootstrap, Hosmer-Lemeshow, binomial grade test, PSI
  report.py    runs everything and writes the report
data/          HMEQ (public teaching dataset, see data/README.md)
reports/       generated figures
MODEL_CARD.md  intended use, data, limitations
```

## Limitations

HMEQ is a public teaching dataset: there is no model owner to answer F2, no
production data and no loan vintages. The results come from one seeded split.
The legacy reconstruction leaves out the K-means segmentation step of the
original notebook. All of this is listed in the report.
